# hellbox — security findings and remediation

- **Repository:** `somoore/hellbox` @ `0250559` (v1.0.27), working tree had no uncommitted changes.
- **Scanned:** 2026-11-02. Scope: 77 tracked source files (Rust CLI + loopback proxy, capsule
  Python/shell, Dockerfile, CloudFormation, GitHub Actions, docs). Untracked `rs-cli/target/`
  was excluded from review (it is build output; the gitleaks hits there are rustdoc prose).
- **Tools:** semgrep (7 results / 3 rules), bandit (15), gitleaks (13 in `target/`, 0 in
  history), trivy (6 misconfigs, 0 CVEs, 0 secrets), hadolint, shellcheck, cargo-audit /
  cargo-deny (0 advisories over 340 crates), `cargo fmt/clippy/test`, the repo's seven
  `scripts/check-*.sh` gates, plus manual review.
- **Team roles:** project manager (01), application security (02), pentester (03), devil's
  advocate/adjudicator (04), QA (05). Verdicts follow 04; reachability follows 03.
- **Verification baseline:** `cd rs-cli && cargo test --features proxy` → **41 passed** before
  the changes, **48 passed** after (7 new regression tests).

## Residual risk

1. **The data-plane cookie is still port-agnostic.** RFC 6265 gives no port isolation, so other
   `127.0.0.1` services receive `hellbox_control` while `hellbox open` runs. Its lifetime is now
   1 h, it authorizes the game stream/input only, and control needs a separate page-injected
   token plus a same-port Origin — but a local process that harvests the cookie can still fetch
   the served page and read that token. Only removing the ambient credential entirely (a Unix
   socket, which loses in-page suspend/resume) would close it. Documented in
   `docs/security.md`.
2. **The capsule still has root processes.** The supervisor, readiness hook and Xvnc run as
   uid 0. The three network-facing stream daemons were moved to `app` and Xvnc is
   loopback-only, but the full `USER app` refactor (`/run`, `/var/log`, `runuser`, X socket
   ownership) needs a capsule cloud build to validate; a boot break would otherwise be silent.
3. **`capsule/Dockerfile:39` still masks dnf failures (SEC-07)**, and the runtime libs are only
   partially checked by the `ldd` gate.
4. **`Sec-WebSocket-Protocol` is forwarded verbatim.** The pentester could not prove that AWS
   uses it to select a port or that `allowedPorts` is enforced on it; stripping it is a
   hardening step that needs live-endpoint verification.
5. **Unused capsule wheels (SEC-11)** remain installed until `requirements.txt` can be
   regenerated and validated with a cloud build.
6. **QA process gaps remain:** only the gitleaks job is a required check (QA-01), the capsule
   Python has no tests (QA-03), and the PowerShell installers are unparsed (QA-06).
7. **Local tooling unavailable:** `cfn-lint` is not installed and the Homebrew `flake8` shim is
   broken on this host. Neither file set changed (no CloudFormation/Python edits), and the CI
   commands are unchanged apart from the version pins; `cargo`, `shellcheck`, `hadolint`,
   `node`, `jscpd`, `gitleaks` and all six non-network `scripts/check-*.sh` gates were run.
